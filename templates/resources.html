Guides

Short, practical paths. Each one takes a few minutes and uses only what ships in the repository.

Quick start for scientists

Inspect a score, check its inputs and reproduce it.

  1. Open Mission Control and pick Mars · Jezero Crater.
  2. Read the score breakdown: each feature's share of the weighted distance, missing features and confidence.
  3. Open Science & validation for the PCA atlas, K-means classes and reference-site checks.
  4. In the Data Hub, open the harmonized grid, compare cleaning profiles and download CSV.
  5. Reproduce the ranking with POST /api/similarity (see APIs).

Quick start for engineers

Find terrain your rover can actually drive.

  1. In Mission Control, turn on rover mode and set the slope limit (5–30°).
  2. Regions qualify when at least 50% of land cells are under the limit. The filter never changes scores.
  3. Open a region for its refined test point (~1 km cell) and the day/night thermal swing.
  4. Use the Mission Console to characterize a custom point from live NASA data.
  5. Script it: POST /api/similarity with rover_mode and max_slope.

Quick start for educators

Show why a desert on Earth can stand in for Mars.

  1. Start on the home page, then open Mission Control.
  2. Choose Moon · Apollo 15 and compare the two globes side by side.
  3. Open Site Explorer and click cells on the Atacama and Merzouga maps.
  4. Use the Science communication card for the closest and most different features.
  5. Print the mission report as a handout (Print / Save as PDF).

How to run a mission

The interactive path, from target to report.

  1. Pick a preset target or click the target globe to define a custom region (25, 50 or 100 km radius).
  2. Check the region summary: cell count, usable features and physical values.
  3. Choose the Earth zone (Atacama or Merzouga), cleaning profile and data mode, then run the analysis.
  4. Compare ranked regions, the similarity ring and the per-feature breakdown.
  5. Open Report to build the dossier. The AI narrative is optional; a deterministic summary is used otherwise.

How to use Agentic Auto Mode

One request, the whole pipeline, with a visible step log.

  1. Open Auto Mode and enter a target (Moon or Mars preset, or latitude and longitude) and an objective.
  2. Choose data mode (bundled or auto for live NASA acquisition) and a cleaning profile.
  3. Start the mission. Steps run in order: plan, acquire, clean, analyze, agents, report.
  4. Each step shows its state and detail. A step that cannot run is marked skipped or failed, with the reason.
  5. Open the result: top regions, cleaning report, live evidence, agent trace and report link.

How to use the data API

List, filter, clean and download every dataset.

  1. List datasets: GET /api/data/datasets.
  2. Read columns, statistics, flags and provenance: GET /api/data/datasets/<id>.
  3. Page through rows with limit, offset, bbox and columns.
  4. Add cleaning=strict (or robust) and read the cleaning report in the response.
  5. Add format=csv to download (up to 200,000 rows per request).

Run TwinSite locally

# web app (Flask, port 5050): pages, /api, bundled data
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python backend/app.py                     # http://127.0.0.1:5050

# optional: platform API (8080) + worker for /v1, agents and live data
PYTHONPATH=backend:. python -m twinsite.api
PYTHONPATH=backend:. python -m twinsite.jobs
# or start all three with: make dev

# optional: build the Mission Console served at /console/
cd frontend && npm ci && npm run build

AI is optional. Core analysis, ranking and reports work without any key. To enable the assistant, report narrative and AI agent roles, set provider keys on the server (for example GROQ_API_KEY) in an untracked .env. Keys are never sent to the browser.

Guarantees

  • AI outputs that cite evidence IDs not present in the evidence packet fail validation, and the router moves to another provider.
  • A role is reported as executed by AI only when a real provider call returned, or when a cached response from an earlier real call is reused and labelled as cached.
  • Without configured providers the AI roles record a fallback with the reason. Results and scores are unchanged.
  • One role's failure never stops the others; the trace records every role's execution and issues.

Algorithms

Deterministic, inspectable and configured in backend/utils/config.py. A score of 100 means an identical profile on the shared normalized scale; it is not a probability of mission success.

Similarity score

effective weight = nominal weight × (1 − 0.30 × target uncertainty)
                                  × (1 − 0.30 × Earth-cell uncertainty)

distance = √( Σ effective_weight × (Earth_feature − target_mean)² / Σ effective_weight )
score    = 100 × (1 − distance)
  • Target values are averaged over a circular window (50 km for presets). At least four shared features are required.
  • Elevation is excluded: each body uses a different reference surface (geoid, areoid, sphere).
  • Up to ten regions are ranked, at least 25 km apart. Confidence is available effective weight over planned weight: an evidence-coverage indicator, not a calibrated certainty.
FeatureWeightFeatureWeight
Slope0.15Night temperature0.20
Roughness0.15Albedo0.15
Relief0.15Thermal inertia0.15
Day temperature0.20Mineral (iron) index0.10

Weights are renormalized over the features that are available for both target and Earth cell.

Cleaning profiles

ProfileBehaviour
rawNo cleaning. Provenance view of the data as bundled.
standard defaultCurrent engine behaviour: quality flags lower weights, rows with a missing value are excluded per feature. Reproduces existing scores exactly.
strictDrops cells whose quality flags mark estimated, proxy or gap-filled values, and applies physical range checks.
robustStrict, plus per-feature median / MAD outlier rejection (|robust z| > 3.5) and optional isolated-cell despeckle.

Every profile returns a report: rows in and out, removals per step and per feature.

Rover filter and refinement

The optional rover filter admits regions where at least 50% of land cells meet the chosen 5–30° slope limit; it does not alter scores. Refinement searches the ~1 km processed Earth grid inside each region, excludes water and steep cells and minimizes day/night temperature mismatch; without target temperatures it picks the lowest qualifying slope. A qualifying point may be absent.

PCA and K-means

PCA projects six environmental features into two dimensions for the atlas. K-means clusters slope, roughness and relief, choosing k from 3 to 6 by silhouette score. Training samples up to 3,000 cells per body. These views explain the landscape; they never determine the similarity score.

Validation

Five published analog sites (Licancabur, Yungay and Salar de Pajonales in the Atacama; the MARS2013 Weyprecht and Payer camps near Merzouga) are checked after ranking: the closest scored cell within 30 km, its percentile and the nearest ranked region. Reference sites never train the models or change the ranking.

Glossary

Analog site
A place on Earth whose terrain or environment resembles a target on another body, used for testing and training.
Harmonized grid
Moon, Mars and Earth data resampled to comparable regions with the same feature columns.
Normalized feature
A feature rescaled to a shared 0–1 range so different bodies can be compared.
Quality flags
A bitmask per cell marking estimated, proxy, gap-filled or fixed-local-time values.
Slope, roughness, relief
Terrain descriptors: steepness in degrees, small-scale height variation and local height range.
Albedo
The fraction of sunlight a surface reflects.
Thermal inertia
How strongly a surface resists temperature change; hints at grain size and rock abundance.
Cleaning profile
A named, reproducible set of data-cleaning steps: raw, standard, strict or robust.
MAD
Median absolute deviation, a robust spread measure used to reject outliers.
PCA / K-means
Dimensionality reduction for the atlas, and clustering into terrain classes.
Evidence ID
An identifier for one observation in a run's evidence packet. AI claims must cite these.
Release gate
Deterministic rules deciding whether a mission result can be released (for example PASS or BLOCK).
Data mode
bundled uses the repository grids; auto adds live NASA acquisition for the target point.
AOI
Area of interest: the window around a point used for live characterization.

FAQ

Is TwinSite endorsed by NASA?

No. TwinSite is an independent open-source project built by team AstroWinners for the NASA Space Apps Challenge 2026. It uses public NASA data but is not endorsed by NASA.

Is the similarity score a probability of success?

No. 100 means an identical profile on the shared normalized feature scale. It ignores gravity, atmosphere, pressure and radiation, so treat it as a screening signal.

Why only the Atacama and Merzouga?

They are the two Earth study zones with bundled, validated grids. The platform API can characterize other Earth points live (POST /v1/science/sites), with coverage limits stated in the results.

Do I need an API key?

No. Analysis, ranking, data downloads and deterministic reports work without keys. AI features need provider keys set on the server.

What is sent to AI providers?

Public scientific context only: computed facts, evidence summaries and your assistant question. No accounts, cookies or personal data. See the privacy policy.

Why does /console/ show "not built"?

The Mission Console is a React app that must be built once: cd frontend && npm ci && npm run build. Flask then serves it from frontend/dist.

Why did an Auto Mode step say "skipped"?

A step that cannot run, for example agents when the platform API is not running or live data when a NASA service is down, is marked skipped or failed with the reason. Nothing is fabricated to fill the gap.

Can I reuse the code and data?

The code is MIT licensed. Data keeps its source license: NASA data is public domain unless noted, OpenStreetMap data is ODbL, GeoNames is CC BY 4.0.
