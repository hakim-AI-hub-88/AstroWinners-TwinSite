Open source & contributions

TwinSite was built by team AstroWinners for the NASA Space Apps Challenge 2026 and is developed in the open on GitHub.

  • Bug reports, data corrections and ideas are welcome as GitHub issues.
  • Pull requests are accepted under the MIT License. Please never commit secrets, API keys or .env files.
  • Scientific claims should cite their data source; results must not be fabricated when a source is unavailable.

Privacy

  • No accounts. TwinSite has no sign-up, login or user profiles.
  • No tracking. No analytics, advertising or tracking cookies. Pages load fonts from Google Fonts and the dashboard loads libraries and map tiles from public CDNs and tile services, which receive standard request information such as your IP address.
  • What you enter. Targets, coordinates, mission options and assistant questions are processed on the server to produce results. Auto Mode missions and platform runs are stored on the server so you can reopen them.
  • AI providers. When AI is configured, the server sends public scientific context to the provider: computed facts, evidence summaries and your assistant question. Do not type personal information into the assistant. API keys stay on the server.
  • Public data services. Live characterization sends the requested coordinates (never personal data) to NASA, AWS Open Data, OpenStreetMap and geocoding services.
  • Server logs. The web server may record standard request logs (time, path, status, IP address) for operation and security.

Acceptable use & scientific disclaimer

  • TwinSite is a research and education tool and a research prototype. It is not endorsed by NASA and is not an operational mission-planning system.
  • Similarity scores compare surface properties on a normalized scale; they are not probabilities of mission success. Verify results with primary data and field expertise before any operational decision.
  • Please use the public APIs reasonably: no automated bulk scraping of live endpoints, and respect the usage policies of the upstream data services.
  • Do not use the site to attack, overload or probe the service or its upstream providers.

Contact

Questions, corrections and security reports: open an issue on GitHub. For a security problem, describe it without publishing exploit details and ask a maintainer for a private channel.
